Data Representation

In Python, data can be represented in three groups discussed below. In any programming language, data is stored in a container called variable. This allows us to refer to and manipulate the data later. In Python, defining a variable is straightforward.

variable_name = variable_value

We may think of a variable as the name of the container and its value as the content held inside it. We are allowed to use and/or modify the value as needed.

mystery_box = 'IPhone'

# a container called *mystery_box* has a value of *'IPhone'* in it.

Now, you may ask, What can I can name a variable? Are there any conventions I should be aware of?

In Python, variable naming follows specific rules and conventions.

  • Avoid keyword: A syntax error is returned when a keyword is used as a variable. Usually, editors display a red squiggly underline under such a variable name.
  • Meaningful name: While we can name a variable almost anything, using a name that reflects its purpose is best practice.
  • snake_case: Using lowercase words separated by underscores for a variable name follows PEP8—standard Python style guide.

Abstract Data Structures

Primitive data representation are great for simple tasks, but they fall short when things get more complex. That’s when built-in data structures like lists and dictionaries come in. We’ll introduce their definitions here and dive deeper into how they work in future posts.

List

A list is a collection of elements and each of them is automatically assigned to an index. Forward indices start at 0 for the first item on the left and increase by one for each following element. In practice, you access an element’s values via its index. Let’s take a look at an example.

Dictionary 

dictionary_name = {key_1: value_1, ..., key_n: value_n}

Another common and powerful data structure is the dictionary. Think of a regular dictionary book: a word has a meaning(s) and no word appears more than once.

A dictionary in Python is created in a similar fashion where it is a collection of two-part elements and each unique key has a specific value. In a dictionary, an item’s value can be retrieved using its key in lieu of index. Here’s a simple example.

Why Functions?

Imagine you want a machine to make a sandwich for you every morning.

  • It’d be time-consuming to tell it all the steps every single day just to do one job. Wouldn’t it be better if it receives one line of request and automatically undertake all the tasks. That’s exactly what functions are for. It lets us wrap a block of code into one reusable command, that we just need to call the function to handle the work rather than rewriting the entire instruction.
  • Let’s say there are many steps for this sandwich-making process. Sure, you could certainly put all the actions in one go—write all the tasks in one function. But it will improve readability if we separate the tasks into logical parts—one for preparation and another for cooking. As such, we know exactly how to allocate a set of actions to one block of time and reuse those sets in other recipes.

What is a Function?

In Python, a function is a reusable block of code that

  • Takes parameters (inputs), performs an action within itself, and optionally returns outputs.
    • Might not have inputs or outputs.
  • Must start with the def keyword.
  • Should end with the return keyword.
    • If no outputs, put return None.
  • Should be named with a verb to indicate its action and written in snake_case.
    • Default parameters must follow non-defaults.
    • Parameters can be set to default values but they can take other values.
    • Body must be indented.
✅ # default arguments come last
def compute_total_income(bonus, salary = 100000):
    # function body

❌ # default arguments are in wrong position
def compute_total_income(salary = 100000, bonus): 
    # function body

Logarithm Function $\log({x})$ has a couple of extremely useful properties:

  • $\log({1}) = 0$
  • It is monotonically increasing, meaning that $\text{if } x_1 < x_2, \text{ then } f(x_1) < f(x_2)$.

These properties are applied in Optimization Algorithms problems which are everywhere in Machine Learning.

  • When we try to maximize a function, evaluating its logarithm is often computationally easier and faster than the function itself while the location of the maximum stays the same.
  • Logarithms can be used when our focus is on how numbers are relative to each other each other rather than their actual values.
  • Since log of a number grows and reduces much more slowly than the number itself, the program can easily avoid the overflow and underflow issues.

Now you may ask, How do I know which function(s) to use provided a problem?

That’s a great question! Let’s look at an example and we’ll walk through the thought process to develop and improve a solution.

Design a Loss Function
In Information Theory, we aim to measure the surprise of an event. A more surprising event is less likely to happen, which interprets more information. $$Information(x) = \log{\frac{1}{p(x)}} = -\log({p(x)}).$$ Below is a descriptive example involving basic probability.
Problem statement: There are ten balls, nine reds and one blue, in a basket. If you pick up a ball from the basket, would getting a red or blue surprise you more?
Breakdown:
  • $R$ and $B$ are the events of getting a red and blue ball, respectively.
  • $E$ is the event of getting a ball.
  • $p(E)$ is the probability of something happen or our believe.
  • $s(E)$ is the level of surprise.
  • $f(p)$ is the symbolic level of surprise.
Idea: If $p(E)$ is higher, $s(E)$ and $f(p)$ are lower. This means $p(E)$ is disproportional to $s(E)$ and $f(p)$.
  1. We should first compute the probability of getting a ball.
    • $p(R) = \frac{9}{10} = 0.9$
    • $p(B) = 1 - p(R) = 0.1$
    This implies that the event of getting a red ball is more surprising whereas the opposite goes for getting a blue ball.
  2. Since $p(R) > p(B)$, we want $s(R) < s(B)$. There are two ways to build $s(E)$ satisfying this condition.
    • A linear function $s(E) = 1 - p(E)$
    • A non-linear function $s(E) = \frac{1}{p(E)}$
    Non-linearity has more interesting properties, so we choose it for $s(E)$.
  3. Have in mind that $p(E) \in [0, 1]$, so $s(E) = \frac{1}{p(E)} \in [1, \infty)$. This means $s(E) = 1$ shows no surprise, which is mathematically strange. It'd be more logical to have no surprise as $0$.
  4. We desire to achieve the level of surprise in $[0, \infty)$ instead. Note that two important properties of logarithm are
    • $\log({1}) = 0$: helps convert $1$ to $0$ as wanted
    • Logarithm is monotonic: $f(p) = \log({s(E)}) = \log{\frac{1}{p(E)}} = -\log({p(E)})$ is proportional to $s(E)$ as we need $f(p)$ also interprets the level of surprise.
  5. Computing $f(p)$ is more convenient that $s(E)$ since the logarithmic graph approaches $\infty$ significantly more slowly than that of $s(E)$.
The solution is improved with steps 4 and 5, but it can be stopped at step 3.
Design the Softmax Function
We commonly use the Softmax Function in Machine Learning. For instance, given a picture, we want to measure how much the object and background are related.
Problem statement: Given a list of data, what is the percentage of each data over their sum? Note that data can be positive, negative, and zero.
Breakdown:
  • $Z = \{z_1, \cdots, z_n\}$ where $z_i \in (-\infty, \infty)$.
  • $S = \sum_{j=1}^{n} z_j = z_1 + \cdots + z_n$ is the sum of all data in $Z$.
  • $p_i = f(z_i)$ is the probability of $z_i$ over $S$.
Idea: For percentage/probability to make sense, we need to create a non-negative number from negative $z_i$.
  1. Have in mind that $\exp({x}) \in (0, \infty)$ where $x \in (-\infty, \infty)$.
    • $Z = \{e^{z_1}, ..., e^{z_n}\}$ where $e^{z_i} > 0$ as wanted.
    • $S = \sum_{j = 1}^{n} e^{z_j}$.
  2. $p_i = f(z_i) = \frac{e^{z_i}}{\sum_{j = 1}^{n} e^{z_j}}$ is the desired probability.
You can certainly use different bases, but $e$ is standard.


User-defined Functions

In addition to built-in functions, users are allowed to custom functions for specific purposes. Some critical information about user-defined functions is:

  • A function is recommended to be defined at the beginning of the program.
  • A function does nothing until it is called.
  • A function is immediately canceled once its task is completed during the call.
  • A function does not necessarily return a value.
    • The return statement sends a value when the call is finished.
    • return None is recommended if there’s no value to return.

A helpful analogy of a function in a program is a room in a house. We enter when we need to do something inside and leave once we’re done. If we need to take something out of the room, you need to bring a container to hold it. Otherwise, you simply walk in and out empty-handed.

Let’s see this idea in action. When the function is called, any argument passed to it is handed over to a new context where they are processed. Eventually, the function gives out a created-inside-the-function value and shuts down/cancels. Thus, all the variables defined inside the function disappear. If variables inside and outside a function are named the same, the one outside is still accessible to the main program whatsoever.

Let’s implement a simple math problem in Python.

Estimate the Area of a Unit Circle.
Problem statement: Approximate the area of a unit circle.
Breakdown:
  • $r = 1$ is the radius of the circle.
  • $\alpha$ is the angle in degree starting at positive $x-axis$.
  • $A_{est}$ is the estimated area of the circle.
  • $A_{real}$ is the real area of the circle.
Idea: We can break it into smaller equal-sized pieces in a way that we can approximate their area via some area formula. Thanks to the equality, we can scale up to get the estimated area of the circle.
  1. Divide the circle into equal circular sectors:
    • Their angle for each sector is $\alpha$
    • The number of sectors is $n = \frac{360}{\alpha}$.
  2. Create triangles out of those sectors. There are two ways, either an isoceles or a right triangle.
    • An isoceles triangle: $A_{\alpha} = \frac{(r)(r) \sin({\alpha})}{2} = \frac{(1)(1) \sin({\alpha})}{2} = \frac{\sin({\alpha})}{2}$
    • A right triangle: $A_{\alpha} = \frac{height * base}{2} = \frac{\sin({\alpha}) \cos({\alpha})}{2}$.
  3. Those triangles roughly cover the circle, so their area sum is the estimated area of the circle.
    • Isoceles triangles: $A_{real} \approx A_{est} = n A_{\alpha} = \frac{360}{\alpha} \frac{\sin({\alpha})}{2}$
    • Right triangles: $A_{real} \approx A_{est} = n A_{\alpha} = \frac{360}{\alpha} \frac{\sin({\alpha}) \cos({\alpha})}{2}$
The lower the number of triangles is, the larger the gap between those triangles and the circle is and vice versa. In order to reduce the gap/error, we'll increase the number of triangles or decrease $\alpha$ to roughly 0. 


import math 

def estimate_area(alpha):
    '''
    This functions aim to estimate the area of a unit circle
    using isoceles triangle method

    alpha (float): the size of an angle in degree

    return (float): the estimated area of a unit circle
    '''
    # compute sine and cosine
    radian_alpha = math.radians(alpha)
    sin_alpha = math.sin(radian_alpha)

    # compute the alpha area
    area_alpha = sin_alpha / 2
    area = area_alpha * (360 / alpha)

    return area

# test 
print(estimate_area(10))
print(estimate_area(1))

'''
3.125667198004746
3.141433158711032
'''

Basic Conditional Statements

We’ll introduce three types of conditional statements. Note that the else statement is optional for the last two.

  1. if: if ‘if’ is satisfied, do it; otherwise, move on.
  2. if-else: if ‘if’ is satisfied, do it and ignore ‘else’; otherwise, do ‘else’.
  3. if-elif-else: if ‘if’ is satisfied, do it and ignore the rest; otherwise, check ‘elif’ and if it is true, do ‘elif’ and ignore ‘else’; otherwise, do ‘else’.

Imagine there are two or three doors and you have a key that can unlock exactly one of them. You need to check one by one and once you open the right door, you can walk through without checking the rest.

The process of these statements is illustrated using flowcharts which use shapes and arrows to depict steps and decisions as follows.
