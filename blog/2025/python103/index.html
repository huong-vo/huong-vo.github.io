Data Structure

Data structures were created in order for computers to handle data faster. Such speed is not so significant in practice these days since computers’ hardware is upgraded every so often.

A data struture is a format used to organize and store data for efficient data access and management. It also reflects on real life situations, for instance, making a dictionary, a customer lineup scenario, or constructing a family tree.

There are two types of data structures and they are arranged according to their usage frequency from top to bottom.

1D List 

list_name = [element_1, ..., element_n]

A list is a container of elements. As mentioned before a list can consist of different kinds of data representation, but we use just one type for each list in practice, especially numbers since computers only works with them.

list_0 = [] # an empty list
list_1 = [7, -5, 8]
list_2 = [5, 4.7, -2, "hello", 0, True, -1000.1, 5, 5, 5]
list_3 = ["aivietnam", [2, -3, 0, 5]]

The rules for list are:

  • All elements are placed inside a pair of brackets.
  • Every two consecutive ones are separated by a comma.
  • As soon as a list is created, so are its indices.
    • Forward index: starts at $0$ and increases by $1$
    • Backward index: starts at $-1$ and decreased by $1$.
    • list_name[index] is used to access an element with index is less than the number of elements.

We mainly use forward index and maybe, when retrieving the last element, $-1$ from backward index.

list_1 = [7, -5, 8] 
list_1[0]
>>> 7
list_1[-1]
>>> 8
list_1[9]
>>> IndexError

Slicing

Similar to the range(start, stop, step) function, the slicing syntax of list is list[start:end:step].

  • start, end, and step are indices. Their values are all optional.
  • start is $0$ and step is $1$ by default.
  • That end is not specified means until the end on either side depending on step.
a_list = [3, 4, 5, 6, 7, 8, 9, 10]
a_list[:3]
>>> [3, 4, 5]
a_list[6:]
>>> [9, 10]
a_list[0:1000:3]
>>> [4, 7, 10]
a_list[::-1]
>>> [10, 9, 8, 7, 6, 5, 4, 3]
a_list[3:1]
>>> []

$+$ and $*$ Operators

The $+$ operator is to concatenate lists. The $*$ operator is to make multiple copies of a list and concatenate them one by one. The original list remains unchanges unless it is assigned to the addition or multiplication.

list_1 = [7, -5, 8]
list_2 = [5, 4.7, -2, "hello", 0, True, -1000.1]
addition = list_1 + list_2
addition
>>> [7, -5, 8, 5, 4.7, -2, "hello", 0, True, -1000.1, 5, 5, 5]
multiplication = list_1 * 3
multiplication
>>> [7, -5, 8, 7, -5, 8, 7, -5, 8]

The $*$ operator can be used when you want to initialize a list with some default value. For example, a teacher is making a file to input students’ quiz grades later. They will do quizzes = [-1] * 50 because they can avoid typing one number too many times and ensure a student’s grade will not have been put in yet as they see the number.

Explanation
  • It's like two bags, one brand name (original_data) and one replica (copied_data).
  • They look the same but how one is used has no effect on the other.
  • Technically, copy() creates a new list object which lives in a different memory address from the existing list.

enumerate()

Instead of using a regular for loop method to access both indices and values in a list, you can use this method to speed up the coding process.

data_0 = [4, 5, 6]

# print index and value in pairs using enumerate()

    print(index, value)

# The rendered output is

1 5
2 6

List Comprehension 

list_name = [condition_to_branch_x for x in data condition_to_filter_x]

List comprehension is popular among programmers, allowing us to write a simple for loop in only one line.

There are three parts appearing in list comprehension. You may ask: Do I need all of them for list comprehension? Am I reading this from left to right or what?

Let me answer you one by one. The short answer for the first one is no; we’ll discuss it right below. For the second question, well yeah if you read it as an English text block. But, it’s Python language here. We should read list comprehension in the following order.

  1. Looping for x in data.
  2. Filtering condition_to_filter_x.
  3. Routing condition_to_branch_x.

Imagine a company is hiring summer interns using a list of job-seekers. They need to evaluate all of them one by one. They can either accept all the candidates or filter some out.

(Optional) condition_to_filter 

if x_filter_condition

This condition can have if only. Here, the company decides to be selective, setting up an interview for each applicant. If someone passes the interview, they proceed with the internship. Otherwise, they are out.

(Required) condition_to_branch_x 

[if_value if x_if_condition else else_value for x in data]

[if_value if x_if_condition else elif_value if x_elif_condition else else_value for x in data]

The condition must be either if-else or if-elif-else. For the latter, it’s written as nested if-else. A syntax error is raised if else is missing.

Think back about the supposed scenario. All the candidates are joining the internship of the company at this point. Now the supervisor must assign jobs to the interns based on their qualifications. Therefore, it is logical to have if-else or if-elif-else in this part.

Besides, that there is no else means even though an incoming intern has passed the whole hiring process, they must still be qualified for something else to be hired. What about those who cannot meet that “something else”? This makes no sense.

2D List

Real-world data extensively need more-than-one-dimension structure/matrix to represent it. For instance, color image data (at least 3D), gray scale image data (2D), text data (2D). Later on, we’ll use a package called numpy to this matter but use list for now. We’ll focus on two dimension here.

To describe a 2D matrix, we can design a nested list which is a list with each element being a list of the same size. Take data_2d = [[1, 2, 3], [4, 5, 6]].

Plain Language Python Language
data_2d is a box data_2d points to a list object
the box holds 2 name tags a list object contains two pointers
the first tag says “look over here”, which directs to a baby box named [1, 2, 3] the element of index 0 points to another list object with value [1, 2, 3]
the second tag says “look over there”, which directs to another baby box named [4, 5, 6] the element of index 1 points to another list object with value [4, 5, 6]


Since each element of a nested 2D list is a list itself, you can access the elements of this inner list just like generally accessing elements of a list. For example, data[1][2] = 6.

If you want to think about a nested 2D list as a matrix, you can think that each element is a row and each column is formed from items of the same index in baby boxes. As such, the number of rows is that of outer elements and the number of columns is that of inner items in each baby box. In this case, this matrix has 2 rows and 3 columns.

data_2d = [[1, 2, 3], [4, 5, 6]]
num_rows = len(data_2d)
num_cols = len(data_2d[0])
# iterate through a nested list using a nested loop and print the matrix
for i in range(num_rows):
    for j in range(num_cols):
        # print each row
        print(data_2d[i][j], end = ' ')
    print()

'''
The rendered output is
1 2 3
4 5 6
'''

What is an embedded system? No. Python reads code top-down.
Can I write 2 functions A and B where A calls B and B calls A? Why does it give an error when I refer to one before defining it? Yes. Such a situation is called mutual recursion. Python doesn’t execute function definitions which consist of function references. It only starts evaluating when a function is called.
