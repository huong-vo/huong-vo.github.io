Review: Data Structure and List

Data structure is a format for storing, organizing, and manipulating data efficiently. It’s similar to how your things are organized at home. For instance, if our books are all over the place, it may take forever to find one when needed. But if they are placed on the shelves in an orderly fashion, we can quickly locate what we want in a second.

Data structures fall into two main categories: built-in and user-defined. We talked about lists; this time, we’ll focus on other built-in data structures. We’ll learn more about user-defined ones and how to create them later in this Python for AI series.

A list can be one-dimensional, two-dimensional, and multi-dimensional. We talked about the first two with 2D lists being one list nesting another. You can think of these lists as a matrix or imagine them as classrooms’ desks arranged in rows and columns.

Mutable vs Immuatable

Objects are the fundamental building blocks of Python, representing everything in the language. Each object has 3 unique properties:

  • Identity: the memory address of an object, like key in dictionary.
  • Type: the data representation of an object, like integer, string, boolean, or list.
  • Value: the value assigned an object, like value in dictionary.

While the identity and type of an object do not change after its creation, its value(s) can be changeable. The mutability of an object’s type refers to this behavior. I like to think of fake food displayed at restaurants as immutable objects while food served to customers as mutable objects. Note that reassignment—assigning an entire object to something else or some other value—isn’t mutability.

Mutable Immutable
Property CAN reassign a different value to an element or add/delete an element after creation without affecting the object's identity CANNOT reassign a different value to an element or add/delete an element after creation whatsoever
  • allow modification of an existing element provided that the element's identity remains unchanged
Effect
  • two objects of the same value have different identities
  • modify one has no effect one the other
  • two objects of the same value have the same identity
  • object interning technique: optimize memory usage by reusing immutable objects

Why do we need immutable?

It’s true that mutability offers flexibility, letting us modify objects in-place without taking up additional memory. Ironically, this strength is also its own weakness. Anyone can change a mutable object’s value(s) either by accident or with a bad intention like hacking.

A mutable object can pose a safety risk whereas an immutable one is more protected. Immutability helps preserve data security and integrity, which is a critical role player in safeguarding digital information.

You may notice that there is more than one way to define a tuple—Unlike lists’ brackets, parentheses are optional for tuples. The last three options allow tuple unpacking, which will be introduced shortly. Like lists, tuples can have elements of different types.

Operators, Methods, and Built-in Functions

Except for being immutable, a tuple’s attributes are very similar to a list’s.

  • They are both ordered.
  • Their elements are accessed, retrieved, and traversed through via indices.

However, because of its immutability, a tuple has way fewer operators and built-in methods than a list does. Use dir() to see them. All previously mentioned built-in functions for lists are supported in tuples.

Swapping Function

There is no built-in function that switches positions of elements in a tuple, but we can certainly write our own function to do so. Let’s take a look.

Without Tuple With Tuple 

'''
take two numbers and swap them
use dummy_a to keep value of a 
assign b to a
assign dummy_a to b
return tuple (a, b)
'''
def swap(a, b):
    dummy_a = a     
    a = b           
    b = dummy_a     
    return a, b     
# test
v_1, v_2= 7, 8
swap(v_1, v_2)

>>> (8, 7)



'''
take two numbers and swap them
store swapped pair in dummy varible
a has value of b and vice versa
return tuple (a, b)
'''
def swap(a, b):
    (b, a) = (a, b)
    return a, b 
# test
v_1, v_2= 7, 8
swap(v_1, v_2)

>>> (8, 7)

Set

set_name = {element_1, ..., element_n}

Beside this rule, a set can be created using set comprehension as follows.

a_set = {i * i for i in range(7)}
a_set
>>> {0, 1, 4, 36, 9, 16, 25}

Unlike lists and tuples, sets are:

  • unindexed: no index is assigned to elements.
  • unordered: elements may not be shown in the same arrangement as in creation.
  • their elements are unique.

Sets are useful when element order isn’t important.

Even though sets can have elements of different types, their elements must be immutable—that is, of a unhashable type. This ensures no element duplication in a set.

Like sets in Mathematics, Python’s sets also perform common set operations like union and intersection. Not only that, sets support other methods such as adding elements. If you’re familiar with SQL or read SQL for AI 101, you might notice some similarities between SQL operations and those in Python.

Dictionary

dictionary_name = {key_1: value_1, ..., key_n: value_n}

Why do We Need Dictionary?

As far as we know, lists, tuples, and sets have the following characteristics:

  • list: mutable, indexed, ordered, duplicates allowed
  • tuple: immutable, indexed, ordered, duplicates allowed
  • set: mutable, unindexed, unordered, duplicates not allowed.

Each of the characteristics has its own pros and cons. Ideally, we’d something that combines possibly the best features of all. That’s where a dictionary comes in.

  • key-value pairs: keys can have any meaningful name.
  • mutable: you can add/delete a key-value pair and update value of some key.
  • indexed: keys play an index role.
  • ordered: a new element is added to the end or a given position.
  • duplicates not allowed: keys are unique thus can only be of an immutable type.

Delete an Item

As we mentioned before, keys of a dictionary are unchangable in Python whereas the values can be modified. To delete a value of an item, simply set it to None or an empty data structure via its key. Deleting a key deletes the item itself.

Use popitem() to remove the last item and it returns a tuple of that item’s key and value.

fruits = {"banana": 7, "apple": 5, "orange": 8}

# test
removed_fruit = fruits.popitem()
print(f"removed_fruit: {removed_fruit}")
print(f"fruits: {fruits}")

Application in AI

You may wonder: Where do we need these data structures in AI? Well, to name a few examples,

  • Tuple: IOU (intersection-over-union) and NMS (non-maximum suppression)
  • Set: Text embedding and text classification
  • Dictionary: Image histogram It’s alright if you know none of these. We’ll discuss a couple of them in a moment.

Text Classification Using Set

A text classification problem in Machine Learning involves categorizing texts into different groups. Some examples are checking if a comment on social media is positive or negative and checking whether an email is a spam. For computers to understand and work with texts, we must convert them into numbers because computers can only operate on numerical data. This task contains two steps:

  • text preprocessing (standardization)
  • text embedding (vectorization).

On top of them, the whole process also contains inputing text samples and interacting with numerical data via layers in machine learning algorithm.

Consider a corpus—a large collection of text such as words, phrases, and sentences. For convenience, take a small corpus with two following samples:

  • sample 1: “We are learning AI”
  • sample 2: “AI is a trending topic”.

The practical process may entail resolving specific issues arising along the way, but we’ll cover main steps in text preprocessing and embedding. This example shows just one way to convert text to numbers.

  1. Clean and standardize all the text, that is, punctuations removed, lowercase, and so on.
  2. Build vocabulary from the corpus:
    • Add words from the corpus to the vocabulary
    • Can add words not in the corpus to the vocabulary
    • Assign a number to each word as their’s unique identity.
  3. Separate each element in the corpus into a list of words.
  4. Encode each word of such a list into a number from the vocabulary.

You may wonder, How can I build vocabulary? Which tools should I use?

Let’s look closer.

  • Our vocabulary can only have words. What can you use to convert two sentences into words? One Google search will do it.
  • Both have the word ‘AI’ that cannot be repeated when added to the vocabulary. Which structure doesn’t allow repetition? Either a set or dictionary is acceptable. At this step, we only need separate words, so a set is our choice here.
  • We want to assign each element a number. But a set is unordered, so it’s cumbersome to control what number is corresponding to a word. Now, we need an ordered structure. Which one is it? A list, tuple, or dictionary are all good.
  • Note that if we use dictionary, we’ll have words as keys and numbers as values, so we can find an encoded number for each word.

Gray-scale images can also be handled the same way since they are represented by a 2D matrix.
