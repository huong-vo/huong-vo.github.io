Review: Data Structure and List

Data structure is a format for storing, organizing, and manipulating data efficiently. Like how your things are organized at home, for example, if your books are all over the place, it may take forever to find one when needed. But if they are placed on the shelves in an orderly fashion, you can quickly locate the one you want in a second.

Data structures fall into two main categories: built-in and user-defined. We’ll focus our attention on the former. We’ll learn more about the latter and how to create one later in this Python for AI series.

A list can be one-dimensional, two-dimensional, and multi-dimensional. We talked about the first two with 2D lists being one list nesting another. You can think of these lists as a matrix, or imagine them as desks arranged in rows and columns, like in a classroom.

Mutable vs Immuatable

Objects are the building blocks of Python, representing everything in the language. Each object has 3 unique properties:

  • Identity: the memory address of an object, like key in dictionary.
  • Type: the data representation of an object, like integer, string, boolean, or list.
  • Value: the value assigned an object, like value in dictionary.

While identity and type does not change after creation of an object, values inside can be either changeable or not. The mutability of object types refers to this behavior. I like to think of the fake food displayed in Japan as immutable objects while the food served to customers as mutable objects. Note that reassignment (i.e., assigning an entire object to something else or some other value) is completely different from mutability.

Mutable Immutable
Property CAN reassign a different value to an element or add/delete an element after creation without affecting the object's identity CANNOT reassign a different value to an element or add/delete an element after creation whatsoever
  • allow modification of an existing element provided that the element's identity remains unchanged
Effect
  • two objects of the same value have different identities
  • modify one has no effect one the other
  • two objects of the same value have the same identity
  • object interning technique: optimize memory usage by reusing immutable objects

Why do we need immutable?

It’s true that mutable is flexible, which helps modify objects as wanted without taking up more room. Ironically, this strength is also its own weakness. Anyone can change in a mutable object either by accident or with a bad intention like hacking.

That means a mutable object can be a safety risk while an immutable one is more protected. The immutability of an object preserves data security and data integrity, which is a critical role player in protecting digital information.

You may notice that there are more than one ways to create a tuple and parentheses are not required for tuples as brackets for lists. The last three allow tuple unpacking, which will be introduced shortly. Like lists, tuples can have elements of different types.

Operators, Methods, and Built-in Functions

Except for being immutable, a tuple’s attributes are very similar as a list’s. They are both ordered and their elements are accessed, retrieved, and traversed through via indices. However, because of its immutability, a tuple has way fewer operators and built-in methods than a list. Use dir() to see them. All the built-in functions for list mentioned previously are supported in tuple as well.

l = list()

Swapping Function There is no built-in function that switches positions of elements in a tuple, but we can certainly write your own function to do so. Let’s take a look.

Without Tuple With Tuple 

'''
take two numbers and swap them
use dummy_a to keep value of a 
assign b to a
assign dummy_a to b
return tuple (a, b)
'''
def swap(a, b):
    dummy_a = a     
    a = b           
    b = dummy_a     
    return a, b     
# test
v_1, v_2= 7, 8
swap(v_1, v_2)
>>> (8, 7)



'''
take two numbers and swap them
store swapped pair in dummy varible
a has value of b and vice versa
return tuple (a, b)
'''
def swap(a, b):
    (b, a) = (a, b)
    return a, b 
# test
v_1, v_2= 7, 8
swap(v_1, v_2)
>>> (8, 7)

Set

set_name = {element_1, ..., element_n}

Beside this rule, a set can be created using set comprehension as follows.

a_set = {i * i for i in range(7)}
a_set
>>> {0, 1, 4, 36, 9, 16, 25}

Unless lists and tuples, sets are unindexed and unordered and their elements are unique. Being unordered means elements may not be shown in the same arrangement as in creation. Sets are useful when element order isn’t important.

Even though sets can have elements of different types, their elements must be immutable, i.e. of unhashable types. This is to avoid duplicating an element by accident.

Like sets in math, Python’s sets also perform common set operations like union, and intersection. Not only that, sets support other methods like appending an item or inserting items. If you know SQL or read SQL for AI 101, you may find the similarities between the two.

Dictionary

dictionary_name = {key_1: value_1, ..., key_n: value_n}

Why do We Need Dictionary? As far as we know, lists, tuples, and sets have the following characteristics:

  • list: mutable, indexed, ordered, duplicates allowed
  • tuple: immutable, indexed, ordered, duplicates allowed
  • set: mutable, unindexed, unordered, duplicates not allowed.

Each of the characteristics has its own pros and cons. We’d like to have a new data structure that has most possible good qualities. That is dictionary:

  • key-value pairs: keys can have any meaningful name.
  • mutable: you can add/delete a key-value pair and update value of some key.
  • indexed: keys play an index role.
  • ordered: a new element is added to the end or a given position.
  • duplicates not allowed: keys are unique thus can only be of an immutable type.
