### **Data Structure**
Data structures were orginally invented to help computers handle data faster. Realistically, speed has become less of a concern due to regular hardware upgrades.

A **data struture** is a format used to organize and store data for efficient access and management. It often mirrors real-life situations, for instance, organizing words in a dictionary, managing a customer queue, or building a family tree. 

There are *two types* of data structures and they are arranged in order of their usage frequency from most to least commonly used. Lists can be used to custom user-defined data structures.

| Built-in   | User-defined |
|:----------:|:------------:|
| List       | Stack        |
| Dictionary | Queue        |
| Tuple      | Tree         |
| Set        | Graph        |
|            | Linked List  |

## **1D List**

```python
list_name = [element_1, ..., element_n]
```

A **list** is a container of elements. As mentioned in the previous post, a list can contain different types of data, but we stick with only one data type per list in practice---especially numbers---since computers internally works with numerical data.

```python
list_0 = [] # an empty list
list_00 = list() # an empty list
list_1 = [7, -5, 8]
list_2 = [5, 4.7, -2, "hello", 0, True, -1000.1, 5, 5, 5]
list_3 = ["aivietnam", [2, -3, 0, 5]]
```

Some basic rules for lists are:
- All elements are surrounded by a pair of *brackets*.
- Every two consecutive elements are separated by a *comma*.
- As soon as a list is created, so are its indices.
    - :arrow_right: **Forward index:** *starts* at $0$ and *increases* by $1$.
    - :arrow_left: **Backward index:** *starts* at $-1$ and *decreases* by $1$.
    - `list_name[index]` *accesses* an element and `index` *must* be less than the number of elements in a list. 

We mainly use forward index, and sometimes use $-1$ from backward index to retrieve the last element.

```python
list_1 = [7, -5, 8] 

# test
list_1[0]
>>> 7

list_1[-1]
>>> 8

list_1[9]
>>> IndexError
```

### **Operators**
We can manipulate lists by performing various operations on them.

#### **Updating an Element**
Lists are **mutable**, meaning their content can be changed after creation. *Mutability* and *immutability* are coming soon in this post. 

```python
list_1 = [7, -5, 8] 
list_0 = []

# test
list_1[2] = 10000
list_1
>>> [7, -5, 10000]

list_0[1] = 5
list_0
>>> IndexError
```

#### **Slicing**
Similar to the *range(start, stop, step)* function, the **slicing** syntax of list is `list[start:end:step]`.
- *start*, *end*, and *step* are indices. Their values are all optional. 
- *start* is $0$ and *step* is $1$ by default.
- If *end* is *not* specified, slicing takes all elements *till the last element* of one side depending on *step*.

Slicing creates an *entirely new* list---changing its elements' value does *not* affect the original list and vice versa.

```python
a_list = [3, 4, 5, 6, 7, 8, 9, 10]

# test
a_list[:3]
>>> [3, 4, 5]

a_list[6:]
>>> [9, 10]

a_list[0:1000:3]
>>> [4, 7, 10]

a_list[::-1]
>>> [10, 9, 8, 7, 6, 5, 4, 3]

a_list[3:1]
>>> [] 
```

#### **$+$ and $*$ Operators**
The **$+$ operator** is to concatenate lists. The **$*$ operator** is to make copies of a list and concatenate them together. The original list remains unchanged unless it is reassigned to the result of the addition or multiplication.

```python
list_1 = [7, -5, 8]
list_2 = [5, 4.7, -2, "hello", 0, True, -1000.1]

# test
addition = list_1 + list_2
addition
>>> [7, -5, 8, 5, 4.7, -2, "hello", 0, True, -1000.1, 5, 5, 5]

multiplication = list_1 * 3
multiplication
>>> [7, -5, 8, 7, -5, 8, 7, -5, 8]
```

The $*$ operator can be used when we want a list to be initialized with some default value. For example, a teacher is making a file to input students' quiz grades later. They can do `quizzes = [-1] * 50` to avoid typing one number too many times and know which grades have been updated.

### **List Comprehension**

```python
list_name = [condition_to_branch_x for x in data condition_to_filter_x]
```

**List comprehension** is favored among programmers, allowing us to write a simple for loop in only one line. A typical list comprehension has three parts as above. 

:question: You may ask: **Do I need all parts for list comprehension? How am I reading this, from left to right?** 

A short answer for the first question is no; we'll discuss the details in a moment. For the second question, well yeah if we read it like an English text block. But, this is Python language; we *read* list comprehension in the following order. 
1. *Looping* `for x in data`.
2. *Filtering* `condition_to_filter_x`.
3. *Routing* `condition_to_branch_x`.

Imagine a company is hiring summer interns using a list of job-seekers. They need to evaluate all of them one by one. They can either accept all the candidates or filter some out.

**(Optional) condition_to_filter** <br>
```python
if x_filter_condition
```
The *filter condition* can *only* have `if`. Here the company decides to be selective, setting up an interview for each applicant. If someone passes the interview, they proceed with the internship. Otherwise, they're out. 

**(Required) condition_to_branch_x** <br>
```python
[if_value if x_if_condition else else_value for x in data]

[if_value if x_if_condition else elif_value if x_elif_condition else else_value for x in data]
```
The *branch condition* *must* be either `if-else` or `if-elif-else`. For the latter, it's written as nested `if-else`. A syntax error will be raised if an `else` is missing.

Now, for those joining the internship of the company, the supervisor must assign them jobs based on their qualifications. This makes it logical to have `if-else` or `if-elif-else` in this part. Besides, without an `else`, it means an incoming intern who has got hired must still be qualified for something else to be hired again. What about those who cannot meet that "something else"? That makes no sense.

## **2D List**
Real-world data extensively need more-than-one-dimension structure/matrix to represent it. For instance, color image data (at least 3D), gray scale image data (2D),  and text data (2D). Later on, we'll use a package called *NumPy* for these scenarios but use list for now. 

We'll focus on two dimensions here. To describe a *2D matrix*, we can use a **nested list**---a list where each element is a list of the same size. Take `data_2d = [[1, 2, 3], [4, 5, 6]]`.

| Plain Language | Python Language |
|----------------|-----------------|
| data_2d is a box | data_2d points to a list object |
| the box holds 2 name tags | a list object contains two pointers |
| the first tag says "look over here", which directs to a baby box named [1, 2, 3] | the element of index 0 points to another list object with value [1, 2, 3] |
| the second tag says "look over there", which directs to another baby box named [4, 5, 6] | the element of index 1 points to another list object with value [4, 5, 6] |

<br>

Since each element of a nested 2D list is a list itself, we can access the inner elements using the same indexing syntax as with regular lists. For example, `data[1][2] = 6`.

A nested 2D list can be thought as a matrix. Each outter element is a row and the columns are formed by items of the same index in each inner list. So, the number of rows is the number of outer elements while the number of columns is the size of the inner list. In this case, this matrix has 2 rows and 3 columns.
```python
data_2d = [[1, 2, 3], [4, 5, 6]]

num_rows = len(data_2d)
num_cols = len(data_2d[0])

# iterate through a nested list using a nested loop and print the matrix
for i in range(num_rows):
    for j in range(num_cols):
        # print each row
        print(data_2d[i][j], end = ' ')

    print()

'''
The rendered output is
1 2 3
4 5 6
'''
```

## **Algorithm and Case Study**
<details class = "bordered-block">
    <summary>
        <strong>Case Study: List and Integral</strong>
    </summary>
    <div class = "bordered-inner-block language-python">
        <strong>Problem statement:</strong> Given a matrix, compute the sum and average of elements of a submatrix. Take a 1D matrix for convenience. 
        <br>
        <strong>Breakdown:</strong> 
        <ul>
            <li> $f(x)$ is the value of the element at index $x$. </li>
            <li> $F(x)$ is the sum of a matrix---all elements from index $0$ to $x$. </li>
            <li> $A$ is the sum of the submatrix---all the elements from one position to another. </li>
        </ul>
        <strong>Idea:</strong> We can use the idea of integral instead of accummulation pattern.
        <ol>
            <li> Let's go over integral method in Calculus first.
                <ul>
                    <li> $F(a) = \int_{-\infty}^{a} f(x)dx = \sum_{\Delta{x} \to 0} f(x) \Delta{x}$: summation of rectangle areas </li>
                    <li> $F(b) = \int_{-\infty}^{b} f(x)dx = \sum_{\Delta{x} \to 0} f(x) \Delta{x}$ </li>
                    <li> $A = \int_{a}^{b} f(x)dx = F(b) - F(a)$. </li>
                    <li> As $c$ is very close to $a$, $F(a) = \int_{-\infty}^{a} f(x)dx + f(c)dx = F(a) + f(c)dx$. </li>
                </ul>
            </li>
            <li> Applied to our problem, we have
                <ul>
                    <li> $F(x) = F(x-1) + f(x)$ </li>
                    <li> $A = \sum_{a}^{b} f(x) = F(b) - F(a-1)$: summation from index $a$ to $b$. </li>
                </ul>
                <br>
                Assume the calculation of $F(x) $ is provided, we just need to know the values of two positions to complete the task. 
            </li> 
            <s>DEMONSTRATION AND EXAMPLE</s>
            <li> The cost to perform this method is low as we can avoid running through the whole submatrix and do accumulation. </li>
        </ol>
        This method is called <strong>Integral Image</strong> and can be found in image data problems like <em>Face Detection in CVPR</em>. 
    </div>
</details>
