## **Introduction to Database**
Microsoft Excel, Google Sheets, or Airtable are tools used to arrange data and perform basic calculations mainly for individual purposes. But they have certain drawbacks when it comes to managing an enormous amount of data. Take customers for a shopping store. On a spreadsheet, if one customer places an order with two different products, there need be at least two rows to store them. This means the customer's relevant details are unnecessarily duplicated. When their information changes, updating it can be an extremely inconvenient and error-prone. 

CRUD is an abbreviation of four basic operations in data management: create, read, update, and delete. Is there a quick and precise structure that allows data storage and manipulation efficiently? 

It is a database. From my viewpoint, the main strategy a database provides to interact with data is to divide, relate, and conquer. If the above example is approached using a database, the shopping system can be divided into several tables like customers', products', and orders' information. The separation enables each table to contain unique details, for example, one customer cannot appear in two separate rows in the customers' information table. Updating content barely takes any work. Moreover, since these tables' main subjects are separate, modifying one's content should not have impact on another's.

~~DEMONSTRATION~~

Look at this database closer. The last table is created as a connection between the first two. Each of the first two tables has its own unique index column named primary key. The order table doesn't have its own primary key instead has a foreign key which is made up of the others' primary keys. This is called a relational database, that is, tables in the database have relations with each other.

This answer helps solving some existing issues. But, just like many problems you face at school, at school, or in life, there are always more than one solutions. Here an order details table can be added so that each order has its own primary index rather than just foreign ones. The more complicated a problem is, the more tables there may be. 

### **Database Management System (DBMS)** 
Formally, a database is an organized collection of data stored electronically so that information can be easily accessed, managed, and retrieved. Some common examples that utilize databases are friend and post lists on social media, patient data at hospitals, Youtube video suggestions, or product arrangement at stores. To be specific, Youtube collects videos you have watched to a database and uses its algorithm to show you suggestions based on your preferences. Or stores analyze customers' shopping behaviors to arrange and rearrange their products so they can increase their revenues. 

We only focus on relational database here. We'll talk more about nonrelational databases in [NoSQL for AI](/_posts/2025-2025-07-sql104.md). 

In order for users to interact with databases easily and efficiently, softwares called Database Management Systems (DBMS) were invented. Some examples for relational DBMS are MySQL, Microsoft SQL Server, and Oracle Database. Using these applications, we communicate with databases by Structured Query Language (SQL). 

MySQL works for smaller databases, so that's what we use here, but you may use any suitable application. In addition, it's recommended we install and use MySQL Workbench as a user interface to work with MySQL.

## **How to Create a Database**
When storing data in MySQL, we generally follow the following process:
1. Design the database schema
2. Create tables
3. Insert data
4. Retrieve data
5. Update or Delete Data

**Database Schema** <br>
A database schema is a comprehensive blueprint of the database layout, representing how data is organized and they are related as groups. You may link it with the idea of class in Python ([Python for AI 105](/_posts/2025-06-18-python105.md)). Since it is like a template, there is no data attached. The schema helps you know the solution as a whole. 

The syntax to create a database schema is
```sql
CREATE DATABASE databasename;
-- or
CREATE SCHEMA databasename;
```
After this, creating tables automatically generates a physical schema in the interface so users can keep track of what has been done compared to the design. 

It is possible to delete a schema, but be very careful with using the following statement since you may not be able to restore the database.
```sql
DROP DATABASE [IF EXISTS] databasename;
```
Without `IF EXISTS`, an error is raised when the given database doesn't exists. 

Note that SQL is a case-insensitive language, but it's conventional to capitalize keywords as above.

## :speech_balloon: **FAQ**
Here are some good questions asked during class. The answers to these questions came from either some admin, TA, STA, or members of AIO2025.

| Questions | Answers |
|-----------|---------|
| Is Microsoft Access similar to MySQL? | Yes. Access saves a database in one file and limits its size. So, it is only suitable for mid-level databases while MySQL is faster working with large databases. |
| What do MySQL Community and MySQL Workbench do? | MySQL Community is a place where databases are stored while MySQL WOrkbench is a tool to work with databases. |
| Must keys be integers? | No. It can be of different types. |
| When do we use relational and nonrelational databases in AI? | IoT uses nonrelational databases while knowledge base or graph netweek uses relational like patient data. |
| Can SQL save data in a video format? | Yes. You can save it in a blob/cloud storage and attach its path in tables. |
