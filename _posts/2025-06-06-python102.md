## **Common Errors**
If you've tried some Python exercises, you probably have encountered some of the errors we'll mention shortly. 

### **NameError**
NameError occurs when you try to use a variable or function that hasn't been defined. 

```python
a = 7 
Print(a)

c = a + b
print(c)

def a_function(x): 
    a_variable = 4
    return x * a_variable

print(a_variable)
```

### **SyntaxError**
SyntaxError occurs when a program violates some grammatical rule of the language.

```python
s = 'Hello World"
print(s)
```

### **ZeroDivisorError**
ZeroDivisorError occurs when a program tries to perform division by zero, which is mathematically incorrect.

```python
a = 7
b = 0

c = a / b
print(c)
```

### **TypeError**
TypeError occurs when there is an incompatible data type operation in a program.

```python
a = 5
s = 'AI'

c = a + s
print(c)
```

### **IndexError**
IndexError occurs when a program attempts to access an element of a collection (a list or string) through an index outside the valid range for that sequence.

```python
a_list = [1, "love", "aivietnam"]
print(a_list[3])
```

### **IndentationError** 
IndentationError signifies the incorrect or inconsistent use of whitespace (spaces or tabs) in a program.

```python
a = 7 
    b = 8
print(b)
```

### **ValueError**
ValueError occurs when a program attempts to perform an operation on a value that is of correct data type but makes the operation mathematically invalid.

```python
import math

number = -4
print(math.sqrt(number))
```


### **ModuleNotFoundError**
ModuleNotFoundError occues when a program cannot locate a module that it attempts to import.

```python
import mymodule

print("iloveaivietnam")
```

### **RecursionError**
RecursionError occurs when a recusive functions calls itself infinitely many times, exceeding Python's default recusion limit.

```python
def a_function(n):
    return a_function(n)

a_function(7)
```

Suppose we want to draw a million stars. It'd take forever to complete this task unless we, I guess, desire to be professional star drawers. There must be a way to **avoid such an endlessly repetitive action**. Exactly, it's a loop, which *repeats some action within itself*. In Python, there are two types of loops including `for` and `while` **loops**.

## **For Loop**

```python
# code before for

for element in iterable:
    # code inside for

# code after for
```

A `for` loop is used when the number of times we want to *iterate* over a sequence, also known as an *iterable*.
- An **iterable** can be a string, list, dictionary, tuple, and range().
- An *element*'s name can be almost anything but is usually `i` or `_`. 
- The body *must be indented*.

For now, we'll focus on the `range(start, stop, step)` function. 
- *start* is $0$ and *step* is $1$ by default. Passing arguments to these parameters is optional.
- The *stop* value is required. 
- The loop runs through a range from *start*, increases by *step*, and goes up to but not including *stop*.

Let's look at some examples.

## **While Loops**

```python
# code before while

while condition:
    # code inside while

# code after while
```

- A `while` loop is used when we do *not* know the number of iterations.
- A `while` loop runs as long as conditions are fulfilled.

:warning: *Always* update the condition inside the loop. Or else, we may create/encounter an infinite loop which runs forever unless we force it to quit.

<pre>

    </summary>

## **Keywords Used in Loops**
### **break**
Imagine playing *Where's Waldo?* and we know exactly how many objects there are on the page. Our goal is simple: find Waldo and stop immediately. Also think about a number-guessing game. We'd have to keep guessing until we hit the correct number. The moment we do, the game ends. 

In both cases, we need to use a loop to repeat tasks, but a strong command is needed to exit early when the goal is met. That's where **break** comes in!

The `break` keyword is mainly used to terminate a loop regardless of whether a for loop finishes its iterations or a while loop is no longer satisfied. Simply put, when the program hits the `break` keyword, it *breaks out* of the loop.

### **continue**
Imagine building a machine that scans a conveyor belt of strawberries. The goal is to pick up only the ripe ones and skip the unripe without stopping the belt. Here, a loop goes through every strawberry but magically ignores those unripe. The magic word for this scenario is **continue**. 

The `continue` keyword is to skip the rest of the current round and jump straight to the next. This keyword is less common than `break`.

## **Examples and Exercises**
<details class = "bordered-block">
    <summary>
        <strong>Estimate the Area of a Unit Circle.</strong>
    </summary>
    <div class = "bordered-inner-block">
        <strong>Problem statement:</strong> Approximate the area of a unit circle.
        <br>
        <strong>Breakdown:</strong> 
        <ul>
            <li> $d = 1 - (-1) = 2$ is the diameter of the circle </li>
            <li> $A_{est}$ is the estimated area of the circle </li>
            <li> $A_{real}$ is the real area of the circle </li> 
            <li> $f(x) = \pm \sqrt{1 - x^2}$ are the functions of the upper-half and lower-half circles </li> 
        </ul>
        <strong>Idea:</strong> Since the area of a circle is twice that of the upper-half circle, we can just focus on the latter. We can break it into smaller pieces in a way that we can compute their area via the function of a half circle.
        <ol>
            <li> <strong>Divide the upper-half circle into rectangles.</strong>
                <ul>
                    <li> Their width is $\Delta{x_i}$ </li>
                    <li> Their height is $f(x_i)$ </li>
                    <li> The number of rectangles is $n = \frac{d}{\Delta{x_i}}$. </li>
                </ul>
                The lower the number of rectangles is, the larger the gap between those rectangles and the circle is and vice versa. In order to reduce the gap, we'll increase the number of rectangles. 
            </li>
            <li> Those rectangles roughly cover the half circle, so their <strong>area sum is the estimated area of the half circle</strong>.
                <ul>
                    <li> $\frac{1}{2} A_{est} = \sum_{i = 1}^{n} f(x_i) \Delta{x_i}$ </li>
                    <li> $A_{real} \approx 2 A_{est} = 2 \sum_{i = 1}^{n} f(x_i) \Delta{x_i}$. </li>
                </ul>
            </li>
        </ol>
        This method is called <strong>Riemann Sum</strong> in Calculus and can be written as follows,
        $$A_real = \lim_{\Delta{x} \to 0} A_{est} = \lim_{\Delta{x} \to 0} \sum_{i = 1}^{n} f(x_i) \Delta{x_i}$$.
    </div>
</details>

## :speech_balloon: **FAQ**
Here are some good questions asked during class. The answers to these questions came from either some admin, TA, STA, or members of AIO2025.

| Questions | Answers |
|-----------|---------|
| Can I call a function before defining it? | No. Python reads code top-down. |
| Can I write 2 functions A and B where A calls B and B calls A? Why does it give an error when I refer to one before defining it? | Yes. Such a situation is called **mutual recursion**. Python doesn't execute function definitions which consist of function references. It only starts evaluating when a function is called. |
